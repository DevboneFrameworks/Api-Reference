Remarks

A snapshot is a replaceable cache and never the source of truth, so an unreadable one must not make a stream unwritable. This exception exists to separate that recoverable case from the failures that are not recoverable: a snapshot addressing a different aggregate, invalid metadata, or an event in the tail that cannot be replayed all keep throwing their original exception, because rebuilding would not help and the silence would hide an infrastructure defect.

CommandExecutor handles this automatically — it discards the aggregate, reloads the complete event stream and logs a warning. Code that rehydrates by hand should do the same: catch this exception, build a fresh aggregate, and call Load(IReadOnlyCollection<IStoredEvent>) with the full stream. The instance that threw is faulted and must be discarded.

In practice this means a state type whose shape changed since the snapshot was written — adding or removing a single property is enough, because the payload has to round-trip losslessly. The other cause is a row written by a platform version that used a different snapshot format, which is what makes changing that format a self-healing operation rather than a migration.
