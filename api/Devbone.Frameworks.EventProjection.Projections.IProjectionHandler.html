Builds one application-owned query model on top of the framework-standard raw and merged layers.

public interface IProjectionHandler

Remarks

The raw and merged layers are configuration-only and identical for every application. A derived handler is where code belongs: traversals, aggregations, denormalizations and anything a configured reference join cannot express.

Handlers run in their own consumer stage, so a failing handler dead-letters its own message and never blocks the merged layer. A handler that throws is retried by the transport; a handler that keeps throwing ends in the aggregate's dead-letter destination.

Property Value

string

Remarks

Keep this opaque token stable for unchanged semantics, and increment it when a transformation or output-shape change may require existing query model documents to be recomputed. It is part of the shared registry snapshot and deliberately remains independent of the handler class, assembly version, deployment revision, and storage location.

This version fences invalidations, failure attempts, checkpoints, dependencies, and barriers. Publishing a changed version schedules a resumable scan over current merged inputs, while the fence ensures its work and progress cannot inherit old-definition evidence.

ProjectionName

Gets the stable public name of the query model this handler maintains.

string ProjectionName { get; }

Property Value

string

Remarks

This is what a caller asks progress by, and what it stores in a frozen consistency selection. It must therefore be independent of the handler class name, the collection it writes, its consumer group and its broker addresses — all four are deployment details that change, and a renamed one must not invalidate a name a client persisted.

Must not end in .raw or .merged: those name the framework's own layers, which are answered from the projection document rather than from a handler checkpoint. A handler claiming one would be asked for progress and never consulted.
