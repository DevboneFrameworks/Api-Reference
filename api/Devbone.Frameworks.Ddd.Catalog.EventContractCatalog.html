Remarks

Populated by generated module initializers, so no reflection scan is needed and no assembly has to be discovered: an assembly that declares event contracts registers them the moment it is loaded.

Registration is additive and idempotent per contract. Two different CLR types claiming the same contract name are rejected at build time by the generator; if it still happens across assemblies, the duplicate is surfaced here rather than silently overwritten.

public static EventContractCatalogDocument CreateDocument(string application, IEnumerable<EventContractRoute>? routes = null)

Parameters

application string

Stable application identifier. It is the owner recorded next to every contract, so it must be the same value across releases of the same application.

routes IEnumerable<EventContractRoute>

Configured routes contributed by the composition root, or null when the document covers declared contracts only.

Returns

EventContractCatalogDocument

The document, with contracts and routes in a stable order.

Remarks

Routes are not derivable from the assembly: stream names live in configuration, which is exactly where a shared broker's namespace collisions happen. Supplying them is what makes the document cover the whole namespace instead of half of it.
