Returns

Task<IReadOnlyDictionary<ProjectionEventPosition, DateTime>>

One entry per position that is stored and unapplied, giving the instant the stored event was last touched. A position that has either not arrived or already been applied is absent.

Remarks

This is what separates "slow" from "stuck", and it is asked per aggregate rather than per projection because the cause is upstream of all of them: raw events apply only in contiguous sequence, so an event whose predecessor never arrived holds up every layer above it. Without this probe every request on such an aggregate would burn its full budget, turning one stalled stream into an unresponsive endpoint.

Task<IReadOnlyDictionary<string, ProjectionWatermark>>

One entry per identifier whose progress could be established. An identifier the projection has not reached yet is absent from the result rather than reported as position zero, because "no progress recorded" and "progress at position zero" are different states and only the first one is real.

Remarks

Where progress lives depends on the projection: a framework layer records it in its own document, an application query model in the checkpoint its handler writes. The implementation resolves that; a caller only names the projection.
