Remarks

The pipeline guarantees that Merged is at least as new as Notification.EventSequence. It does not guarantee equality: delivery is at-least-once and later events may already have been merged, so Merged.EventSequence can be greater. Treat the document as current state, never as the state immediately after one specific event, and keep handlers idempotent.

Merged.Metadata identifies the last applied event, including its contract name and event id. This layer intentionally does not carry event payloads: replicating them onto the internal address would double broker volume for data the raw event collection already stores. A handler that needs them reads the triggering aggregate's stored events through ReadRawEventsAsync(long, int, CancellationToken).

ReadRawEventsAsync(long, int, CancellationToken)

Reads one page of the triggering aggregate's events in ascending sequence order, up to the merged position this handler sees.

public Task<IReadOnlyList<ProjectionEvent>> ReadRawEventsAsync(long afterSequence, int maximumCount, CancellationToken cancellationToken = default)

Parameters

afterSequence long

Exclusive lower bound: the page starts with the event after this sequence. Pass 0 for the first page and the last returned Metadata.EventSequence for the next one.

maximumCount int

Maximum number of events in the page, between 1 and 100.

cancellationToken CancellationToken

Cancellation token.

Returns

Task<IReadOnlyList<ProjectionEvent>>

At most maximumCount events with a sequence greater than afterSequence and at most Merged.EventSequence — or Notification.EventSequence when Merged is null after a deletion, which includes the deletion event. Never an event beyond that bound, although later events may already be stored, so the events always agree with the state the handler reads. The page is empty once afterSequence reaches the bound.

Remarks

Only events of Notification.AggregateName and Notification.AggregateId in the notification's tenant are returned. Each event carries its EventMetadata — at least EventName, EventVersion, TimestampUtc, EventSequence and EventId — and its payload as the fold sees it: a protected field is plaintext, or the tag's placeholder (or removed, as the tag's policy says) once the subject's key was destroyed. The payload is a copy the handler may modify. Numbers follow the conversion described for the merged document.

The storage layout of the events stays private to the pipeline; this method is the supported way to read them.

Exceptions

ArgumentOutOfRangeException

Thrown when afterSequence is negative or maximumCount is outside 1 to 100.

InvalidOperationException

Thrown when the context was constructed directly rather than by the pipeline or WithRawEventsForTesting(IEnumerable<ProjectionEvent>), or when the pipeline's raw store is a replacement that offers no event reads.

SubjectKeyRegistryUnavailableException

Thrown when the key service cannot be reached. Let it propagate: the pipeline then leaves the work unsettled and retries it without counting a handler attempt.
