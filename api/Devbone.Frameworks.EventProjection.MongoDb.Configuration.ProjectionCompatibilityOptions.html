Remarks

Turning this off is the supported escape hatch for an application that provably does not project to MongoDB. It disables ValidateCommit(string, IReadOnlyCollection<string>) only, so aggregate commits stop being checked against BSON representability and MongoDB size limits.

It deliberately does not disable the read-side checks in the projection pipeline: those guard an actual MongoDB write, where the limits are physical rather than a policy.

Disabling it in a system that does project to MongoDB moves the failure from a recoverable command error to a permanently dead-lettered projection message and a read model that silently diverges. There is no supported repair for that, because the offending event is already immutable.
