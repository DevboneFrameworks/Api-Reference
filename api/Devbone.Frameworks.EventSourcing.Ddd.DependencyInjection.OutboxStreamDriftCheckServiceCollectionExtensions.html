Remarks

An outbox row keeps the stream resolved at its commit, and the dispatcher and every later replay publish to it. A stream changed in configuration therefore reaches later commits only, and a route version removed from configuration leaves its rows pointing at a stream nothing describes any more.

Once after the host has started, in the background, the check reads the route versions and streams of the unpublished rows and logs a warning per route version that disagrees with the configuration: event id 3050 when the stored stream differs from the configured one, 3051 when the route version is no longer configured, 3052 when the read fails and 3053 when the read reached its limit of combinations. Every warning names the event store and carries row counts and route names only — never a connection string, a row identifier, a tenant or a payload. Startup never waits for the read, and a failing read is logged, never thrown.

Parameters

services IServiceCollection

The service collection.

eventStoreId string

The logical id of the event store whose outbox is read, as the route versions name it — the Gateway's target name, for example. It appears in every warning, so it must be a configuration name, never a connection string.

routing AggregateRoutingOptions

The routing configuration the host writes through. It is validated here; the rows are compared with it as it is when the check runs.

readerFactory Func<IServiceProvider, IOutboxRouteInventoryReader>

Creates the reader of that store's outbox when the host builds its hosted services. Creating it must open no connection; the check reads only after the host has started.

IServiceCollection

The same service collection so calls can be chained.
