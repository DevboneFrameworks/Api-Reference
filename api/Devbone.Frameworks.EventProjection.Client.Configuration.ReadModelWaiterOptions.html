Remarks

One value for every pending reason, on purpose. A cause-aware delay — longer for a stream that is replaying than for a projection one event behind — is plausible and unmeasured, and a guessed heuristic here would be indistinguishable from a tuned one until it was wrong in production.

PollInterval

RegistryCacheDuration

Property Value

TimeSpan

Remarks

Definitions change at deployment boundaries and availability changes when worker capabilities start or expire, while the registry is read on the acceptance path of every request that names a projection. Short-lived rather than permanent, so deployments and expired leases become visible without restarting the API host.

StallProbeAfter

Gets or sets how long a wait runs before it starts probing for a stalled stream. Every probe is an extra query, and almost every wait ends long before this, so it pays only for the ones that do not.

StallThreshold

Gets or sets how long an event may sit stored-but-unapplied before the wait treats the stream as stalled rather than slow.

public TimeSpan StallThreshold { get; set; }

Property Value

TimeSpan

Remarks

A replay legitimately leaves events waiting for a predecessor while it runs, so a short value would call a repair in progress a stall. This is the same distinction the pipeline's own stall detector draws, and it should be set below the pipeline's StallWarningAge so a request gives up before an operator is paged.
