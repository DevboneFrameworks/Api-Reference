Reads the projections a deployment publishes, so a caller's request can be validated and frozen before the command runs.

public interface IProjectionRegistry

Remarks

The registry is a shared store written by the projection worker at startup, not an in-process catalogue. Handlers are registered in the worker while names are asked for in the API host, so a catalogue populated by registration would be empty exactly where it is read and would report every correctly registered projection as unknown.

Resolve at request acceptance, not after the command commits. An unknown name discovered afterwards leaves a durable write with a wait that can never succeed, and the caller cannot tell that from a slow projection.
