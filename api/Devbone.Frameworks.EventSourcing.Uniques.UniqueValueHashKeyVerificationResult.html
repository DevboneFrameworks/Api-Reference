Remarks

Every aggregate stream written through the DDD layer holds one scalar reservation in its aggregate's scope (aggregate:<AggregateName>) under the key AggregateId, whose value is the identity's canonical text, compared case-sensitively. Its owner column carries the same text, so the stored hash can be recomputed from the row alone, without the value being stored anywhere.

The result is one of three states. IsKeyConfirmed: at least one sampled reservation matched, so the key is one the database's writers used. IsKeyRejected: reservations were sampled and none matched, so the key is not the one the stored reservations were written with. Neither: the store holds no such reservation yet, and there is nothing to compare against. A partial match - some rows match, others do not - confirms the key; rows that do not match were written with another key or are reservations under the key name AggregateId whose value is not the owner's identity.
