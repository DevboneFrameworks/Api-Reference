Remarks

On a broker shared by several applications, the Contract name is a cross-application namespace that nothing reserves. Two applications can pick the same name for different payloads, and the mismatch surfaces only when a foreign consumer fails to interpret an event. A catalogue makes that mechanically detectable before deployment instead.

Everything here is resolved at compile time by the bundled generator, so the descriptor reflects the declaration rather than any particular event instance.

Remarks

The version reaches the event through its base constructor, so it is derivable only when the value is a literal or a constant parameter default. An unresolved version is reported as a build warning and makes the version-aware verification rules inapplicable to this contract — it is never guessed.

Remarks

The hash alone cannot classify a change: adding an optional property is allowed without a new version, renaming one is not, and both change the hash. Verification therefore always compares Fields and never trusts this derived value as compatibility evidence by itself.
